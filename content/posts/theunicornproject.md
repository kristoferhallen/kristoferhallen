![The unicorn project book cover](/theunicornproject.jpg#floatleft) The Unicorn project is a book about how to (and how not to) develop software in a large company. How do you go from an inefficient, slow and frustrating work environment to a setup where you deliver value fast and people are happy to go to work? Gene Kim's (the author) answer is DevOps, create teams that understand the business, can work end to end from business need to deployed software and that can do experiments, learn from the deployment and improve. 

This is a novel, not a technical book, easy to read and has many examples that you will recognize if you have worked in a larger company with a legacy code base. If you want a more scientific description of the methods this is described in the book Accelerate: The Science of Lean Software and Devops where Gene is one of the authors. It is a challenge for some companies to adapt to the expectations of fast and efficient software development. If you are in that situation the description of how you can find ways to improve way of working and technical solutions gives hope that for the reader that change can happen. 

I will learn from the five ideals that were introduced in the book, explained e.g. [here](https://www.youtube.com/watch?v=vLHFuQjJR8Y).
* Locality and Simplicity
* Focus, Flow and Joy
* Improvement of Daily Work
* Psychological Safety
* Customer Focus

I also liked the perspective of challenging what you do yourself in the company and what you can outsource. E.g. to get something done quickly you set up a service but after a while you can if you evaluate it realize that it is expensive to run and that there are similar services you can buy that will be cheaper. This I realize also challenges my own mindset, a common pattern is to build things yourself and argue that we need the people and budget to run it because it is important for the company. But is it really? Or is it a blocking investment in the areas that would make a difference for your business?
