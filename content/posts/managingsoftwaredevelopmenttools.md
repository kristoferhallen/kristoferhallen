I had a talk at the [Devlin2025](https://events.responsive.se/devlin2025/konferensdagen-devlin2025?view=Events&id=162&task=civicrm/event/info&reset=1) conference about managing your software development tools. Here is the short version.

# Define a Golden Path, but Avoid a Golden Cage
The recommended, supported ways of doing things. But don't make i a golden cage. It should be possible to test things outside the path and change the path when better solutions are found.

# Own the Function, Not the Tool
The person or group that is responsible to support something in the golden path should be responsible for the function, the problem to solve, not a specific tool. Tools will change, the responsibility stays.

# Buy, Don't Build (Leverage Open Source)
Don't build new tools. Buy, use open source, contribute to open source.

# Implement Disciplined Tool Governance (e.g., Tech Radar)
E.g. regularly update a technology radar. 

# Design for Low Cost of Change (Loose Coupling)
There will always be dependencies but when you decide about integrations consider the cost of change.

# Focus on Total Cost of Ownership (TCO)
When evaluating tools think about the total cost of ownership including e.g. migration and competence build up.

# Apply the '2x or 10x' Rule for Tool Replacement
Have a high threshold. It is always more expensive to change than you think and the value add is many times lower than you think.
