Death to the program! Long live the project.

8 Dec 2024

Maybe a niche thing to reflect on, but some software companies went from projects to programs. Why start projects all the time, let’s just define a never ending project and call it program. In many cases I don’t think it works very well.

  • Programs get the wrong focus. A project exist to deliver a value before a deadline. A program does not have specific deliverables or deadlines. They can have it for activities that are part of the program but the program leadership do not own the responsibility for delivering on time and they tend to instead focus on being busy. Focus tends to go from flow optimization to resource optimization.
  • Programs never end which means that you don’t get natural points when you hopefully celebrate achievements. You also don’t get the natural times to reflect, recover and clean up. You are always busy (see the point above.)

Programs can probably be a good tool when you have a predictable process that you want to run over and over again, usually with similar outputs. This is however not what software developent looks like.

Note to self - reflect on program, project vs DevOps.
